HoudiniMind

Natural language to working Houdini setups — generated, validated, and run live.

Houdini is industry-standard 3D / VFX software. This tool writes its code and executes it automatically.

Why an LLM isn't enough

Ask any LLM for a Houdini setup and it will describe one fluently. Ask it to build one that runs, and it breaks — one mis-wired connection and the simulation silently produces nothing. The hard part isn't generating code that looks right; it's generating code that's correct enough to execute, every time, across six simulation domains.

How it works

Generate → validate → execute → verify. Nothing reaches Houdini until it passes the static gate; nothing counts as done until the graph actually cooks.

01

Retrieve

RAG over 73,000+ chunks from real production node graphs (ChromaDB), split per domain.

02

Generate

The Claude API turns the prompt into structured Houdini Python, constrained by a validated domain skeleton.

03

Validate

Static syntax gate, VEX post-processors, and per-domain wiring checks repair and reject bad output.

04

Execute

Code runs live into Houdini 21 over a TCP bridge — real nodes, real simulation, verified after cook.

What makes it reliable

The interesting engineering isn't the model call — it's the retrieval, validation, and repair layers around it that make the output reliable enough to run unattended.

Grounded retrieval

Real production files

73,657 chunks indexed from real .hip files, so generation follows how setups are actually wired — not generic docs.

Constrained generation

Domain skeletons

Each domain injects a known-good, fill-in-the-blank wiring template into the prompt, killing structural failures at the source.

Deterministic repair

Post-processors

Fixers catch the mistakes the model repeats — e.g. fmod(a,b) → a % b, which VEX has no function for.

Safe API

Helper layer

A small wrapper (_cn, _sp, _si) hides Houdini's footguns like node aliases and explicit output indices.

Per-domain gating

Validators

Ocean checked for the right spectra path, destruction for fracture output indices, KineFX for skin + skeleton both wired.

Live execution

TCP bridge

A custom bridge holds the connection to a running Houdini session — this is what turns "generate" into "actually run it."

Six simulation domains

FLIP

Liquids — particle fluid to meshed surface

Ocean

Spectra, surface evaluation, whitewater

Pyro

Fire and smoke from rasterized sources

MPM

Sand, snow, cohesive materials

Destruction

Fracture, packed RBD, constraints

KineFX

Character rigging and skeletal animation

Not just generation — it answers too

The same retrieval layer powers an Ask mode: a senior-TD assistant that answers Houdini questions directly, with markdown, separate from the build pipeline. One knowledge base, two ways to use it — generate a setup, or ask how one works.
